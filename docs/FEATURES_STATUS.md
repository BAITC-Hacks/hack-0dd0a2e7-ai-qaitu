# FEATURES (1): проверка объёма перед демонстрацией

Работа изолирована в ветке `features/document-review`; `main` не меняется.
Исходная спецификация найдена в `TelegramDesktop/tdata/temp_data/FEATURES (1).md`.
Упомянутый в ней `AGENTS.md` с эталоном и спецификацией оппонента не предоставлен.

## Что добавлено за ограниченный этап

| Блок | Реальное состояние |
|---|---|
| F11 — локальная часть линтера | `LNT-REF`, `LNT-EMPTY`, `LNT-NUM`, эвристические кандидаты `LNT-REF-SEM`. Источники и цитаты, проверка одной редакции, фильтры и страницы. Не весь F11. |
| F9 — экспертное согласование | Чек-лист поверх прежних findings и проверок новой редакции; ручные решения, обязательные имя/комментарий, отдельное подтверждение исправления, журнал SQLite, защита от перезаписи из устаревшей сессии. Word/PDF и JSON-журнал. |
| Режимы A/B/C | Представления проекта, реорганизации и пакета для СД. Переключение без повторного анализа/API. Режимы содержат только реализованные панели. |

F9 не заменяет юридическое согласование. Красный статус: открытые потери,
конфликты или назначенный экспертом приоритет 3. Жёлтый: прочие открытые вопросы,
неподтверждённые исправления, неполнота или предупреждения обработки. Зелёный:
найденные вопросы закрыты, полнота заявлена и нет предупреждений. Это только
статус чек-листа, а не доказательство корректности документа. Автоматический
ущерб из F5 не рассчитывается, экспертный приоритет явно обозначен отдельно.

Старые ошибки линтера показываются справочно и не блокируют новую редакцию.
Обычные отчёты сравнения не смешивают технические замечания с потерями функций.
`document_checks` в полном JSON содержит все проверки обеих редакций;
решения — в отдельном журнале и листе согласования. Экспорты не зависят от фильтров.

## Расхождение H1 с реальными файлами

В переданном оригинале №9 пункты 5.10.2 и 5.10.5 содержат «в части, не противоречащей
п. 5.8.1 и 5.8.2». Пункт 5.8 задаёт запреты, целевые пункты существуют.
Оснований автоматически объявлять ссылки ошибочными или менять номера нет.
В №8 аналогичная оговорка в 5.11.2/5.11.5 ведёт на раздел **прав** 5.8 — линтер
показывает именно эти два смысловых кандидата с исходным пунктом, целями и
заголовком. Это ещё не доказанная ошибка; решение за экспертом.

H2 подтверждён: в оригинальном PDF №8 пункт 5.5.3 содержит только `;`.
Заявленный в спецификации W1 также нельзя безусловно называть полной потерей
квартальной отчётности: периодичность сохраняется в общем контексте 5.1.6.
Будущие ослабления надо моделировать на уровне конкретного назначения, не
возвращать уже устранённую ложную потерю функции.

## Что отложено и почему

| Фича | Что требуется до реализации |
|---|---|
| Остальное F11 | Словарь сокращений, отбор пар противоречий, отдельное подтверждение LLM; тесты точности, а не только наличия результата. Автоправки зависят от F7. |
| F10 — оппонент | Полный `AGENTS.md`, отдельный промпт и поисковые инструменты, проверяемые контрдоказательства, кэш и согласие на внешний API. |
| F4 — симулятор | Библиотека сценариев с доказательствами каждого шага; корректная трактовка W1 и проверка переносов. |
| F7 — Word с исправлениями | Хранение исходного DOCX, надёжная привязка XML к цитатам, минимальные непересекающиеся правки и испытание tracked changes. Текущий Word — лист согласования, не исправленная редакция. |
| F5 — матрица рисков | Подтверждённые находки, компенсирующие контроли, сценарии и сроки. Ручной приоритет F9 не подменяет этот расчёт. |
| F6 — нагрузка | Извлечение должностей отдельно от численности, веса, проверка знаменателя, затем опциональный FTE. Можно брать следующим независимым блоком. |
| F8 — альтернативы | Виртуальная модель перераспределения и настоящий повторный прогон ядра/F4/F5/F6; без этого цифры эффекта недостоверны. |
| F12 — история | Ввод ≥3 явно упорядоченных версий и тест восстановления/«маятника». Вкладка пока не добавлена. |

Нет пустых кнопок, выдуманных баллов/сценариев или заявления о готовности всех фич.
Новые функции работают локально, не требуют новых библиотек и не вызывают API.

## Сохранение и границы безопасности

- База по умолчанию: `.qaitu/reviews.sqlite3` (исключена из Git).
- Другой путь: переменная `QAITU_REVIEW_DB`. Для контейнера нужен постоянный том.
- Решения привязаны к содержимому комплекта и основанию находки. Замена документа
  не переносит старое согласование автоматически. Повторный анализ того же
  комплекта восстанавливает решения после перезапуска приложения.
- База общая для экземпляра приложения, без аутентификации/разделения организаций.
  Использовать как локальный инструмент доверенной команды, не как публичный
  многопользовательский сервис. Имя эксперта самозаявленное, не цифровая подпись.
- История дописывается без удаления предыдущих решений. Не содержит API-ключей
  или полного текста документов; комментарии могут быть чувствительными.
- Ошибка чтения базы не выдаётся за пустую историю: согласование и его экспорт
  отключаются, сравнение остаётся доступным.

## Проверка

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python scripts/check_document_review.py --before /path/to/edition8.pdf --after /path/to/edition9.docx
.venv/bin/python scripts/check_real_documents.py --before /path/to/edition8.pdf --after /path/to/edition9.docx
```

Оригиналы не копируются в репозиторий. В `tests/features/` лежат короткие
анонимизированные примеры, тесты состояния, экспорта и Streamlit; скрипт выше
отдельно проверяет реальные файлы. `--output /tmp/report-directory` у нового
скрипта сохраняет образцы листа согласования для визуальной проверки.

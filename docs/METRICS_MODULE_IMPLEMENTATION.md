# Оценка эффективности и оптимизация

Модуль реализует второй слой анализа из METRICS_MODULE.md и использует оформление `main`. Основное сравнение документов, матрица функций, ИИ-проверка и экспорт ядра сохранены.

## Этапы и результаты

| Требование | Реализация |
|---|---|
| M1 — отчёты | Excel: алиасы, широкие и длинные таблицы, год/квартал/месяц. Word/PDF: таблицы, опциональное извлечение из текстовых фрагментов через OpenAI. Проверка буквальной цитаты и числа. Неясные поля — в очередь человека. |
| M2 — изменения | Адаптер фактических моделей ядра: подразделения, изменения назначений, кандидаты на потери, пересечения и конфликт ролей. Пользователь подтверждает дату и связь с метрикой. |
| M3 — периоды | Строго до/после даты. Пересекающий дату период исключается. Полные месяцы приводятся к кварталам/годам; неполные наборы не заполняются выдуманными числами. |
| M4 — сравнение | Средние сопоставимых периодов; линейный тренд по фактическим датам при ≥3 точках до; приоритет разности разностей для подтверждённого контроля с теми же периодами. Объём дополнительно на FTE при точно соответствующих источниках. |
| M5 — объяснение | Механизм подтверждает человек. Детерминированный оппонент проверяет другие события, штат, план, бюджет, тренд. Опциональные LLM-аналитик и отдельный LLM-оппонент; числовые расчёты и уверенность остаются в коде. |
| M6 — прогнозы | Наступивший срок, достаточное непрерывное покрытие до горизонта, без использования будущих периодов. Pending/inconclusive исключаются из точности. Ручные прогнозы показываются отдельно. |
| M7 — накопление | SQLite: раздельные пространства real/synthetic, дедупликация случая по стабильному ID события, дате, подразделению и метрике. Повторный расчёт заменяет или отзывает прежний случай. Случаи одного периода и подразделения не увеличивают число независимых наблюдений. |
| M8 — действия | Рекомендации с основаниями, ожидаемым направлением, уверенностью, рисками и решением человека. Произвольное назначение функции новому отделу запрещено. |
| M9 — интерфейс | Отчёты/очередь, дашборд, изменение→эффект, прогноз vs факт, рекомендации, база знаний; JSON и Markdown; отдельный переключатель рабочего пространства. |

## Правила интерпретации

- Источник значения содержит файл, SHA-256 содержимого, ячейку/лист либо страницу/абзац и цитату. Для производного сравнения сохранены ID всех исходных значений, включая контроль и FTE.
- Суммы потоков используются только при приведении полной гранулярности. Проценты усредняются, а не суммируются; без числителей и знаменателей это арифметическое среднее процентных показателей, не совокупная доля. Численность при укрупнении — последнее значение периода. Между окнами разной длины сравниваются средние значения одинаковых периодов.
- `delta_abs` процентной метрики выражен в процентных пунктах, `delta_pct` — относительное изменение к исходному значению. При исходном нуле относительное изменение не определено. `normalized_delta` — абсолютное изменение показателя на FTE.
- `is_significant=insufficient_data`: статистическая значимость не оценивалась. Фильтр заметного изменения служит отбору карточек и не является p-value.
- Контрольная группа требует основания от пользователя, отсутствия затрагивающих её событий и совпадающих периодов. Параллельность трендов проверяется как ограничение; сравнение не устанавливает причину. Линейная поправка не моделирует сезонность.
- Уверенность: менее двух точек с любой стороны, опровержение оппонента или отсутствие механизма → недостаточно данных. Неподтверждённый механизм или простое сравнение с замечаниями → низкая. Подтверждённая связь с оговорками → средняя. Высокая требует сильного метода, отсутствия выявленных альтернатив и положительного результата оппонента.
- Один случай — единичное наблюдение. От двух — наблюдение в похожих случаях. Числовое обобщение базы доступно от трёх различных случаев с разнообразием периодов/подразделений; это не обещание будущего эффекта.
- Реальные и синтетические значения, события и прогнозы не смешиваются. В синтетическом сценарии рост ИТ-проверок относится к непрерывному процессу «БВА:ИТ-аудит», а не к фиктивным отчётам ДИТААД до его создания.

## Честные ограничения прототипа

Реальные отчёты с показателями в исходном комплекте отсутствуют. Синтетика предназначена для проверки полного цикла, не для вывода об эффективности Казахтелекома. Вывод об ослаблении локальной периодичности в демо — заданная гипотеза; общая обязанность ГА отчитываться ежеквартально сама по себе не исчезает.

В фактическом ядре нет `TimelineEvent`, `Scenario` и редактора правок. Поэтому реальный автоматический прогноз и ссылка на несуществующую правку не генерируются. Синтетические прогнозы явно обозначены; пользователь может добавить ручной прогноз с горизонтом и исходным событием.

PDF-сканы без текстового слоя требуют OCR вне этого прототипа. Неизвестная верстка, неоднозначные единицы и конфликты значений требуют ручного подтверждения, а не догадки. ИИ-извлечение опционально и ограничено размером входа; ошибки не раскрывают содержимое ключей или ответов провайдера.

## Проверка

Запуск: `python -m unittest discover -s tests -q`.

Проверяются исходное ядро, загрузка и цитаты, числовая арифметика и границы периодов, контроль, FTE, уверенность и альтернативы, горизонты прогнозов, сохранение/дедупликация базы и решений, отсутствие причинных утверждений, маркировка синтетики, отказ при смешивании и отключение дополнительного модуля.
